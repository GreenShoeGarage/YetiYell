    FIELD NOTES

    Know what you’re testing.

    A signature match is evidence about a packet, not proof of a product.

    v1.0 bench acceptance

    These are operator-entered results for your equipment. They do not change the release’s unverified hardware status.

    What this release does

    YetiYell v1.0.0-rc.6 transmits 33 BLE profiles and 9 ordinary Wi-Fi beacon profiles. Seven are negative controls. Each profile exercises a specific rule in SquachWatch.

    It uses a stable static-random BLE address per profile and locally administered Wi-Fi addresses, except for the two explicit address-prefix fixtures. Keep only one YetiYell transmitter active for an unambiguous result.

    Wi-Fi profiles create a password-protected standalone lab AP. No internet connection, portal, or credentials are collected. The board never starts a transmission at boot.

    Read the log, then the alert

    1. Check SquachWatch’s TYPE FILTER for the profile you chose.
    2. Review confidence filtering, ignored devices, snooze, and alert cooldown.
    3. Run one profile while watching the detector log.
    4. Record the observed type, optional RSSI and latency, and your notes.

    iBeacon is disabled by default on SquachWatch. Older versions may flag the Raven near-match control because they used a broader UUID range.

    Make comparisons repeatable

    Keep distance, orientation, Wi-Fi channel, and power consistent between runs. Start with the default 20 seconds so the receiver has time to scan. BLE is non-connectable legacy advertising.

    The app records the transmitter’s identity and timing; it does not read SquachWatch automatically. A lack of an alert alone is not a failed detection. Use the log as your observation source.

    Choose Inconclusive when the run was interrupted or conditions make the result uncertain.

    Coverage boundaries

    This version includes two fixed address-prefix fixtures. It does not test arbitrary vendor MAC prefixes, deauthentication floods, evil-twin behavior, drone Remote ID, Bluetooth Classic, 5 GHz, or LoRa. “Deauther name” sends only the documented Wi-Fi network name.

    No synthetic result in YetiYell counts as over-the-air validation. The physical flash, RF path, and detector response need to be checked on your bench.

    Profile reference: SquachWatch source snapshot ↗.

    Host it anywhere static

    Upload the contents of server/ from the download to an HTTPS directory. Everything needed at runtime is included: app, flasher, and firmware. No build step, account, database, or CDN is required.

    For local use, serve that folder on http://localhost. Opening the HTML directly as a file is not supported. Desktop Chrome or Edge is required for USB.

    After a successful first load, offline caching keeps the bench and firmware available. Your browser may evict cached data; retain the download for dependable offline work.

    When USB won’t cooperate

    Close Arduino Serial Monitor, PlatformIO, other YetiYell tabs, and any other app using the port. Check the data cable and the board’s USB driver.

    Hold BOOT while the flasher connects, then release it once the chip is detected. Press EN/RESET after flashing if the application doesn’t answer.

    If this app is embedded, open it in its own browser tab to allow USB access. Keep this tab visible during a test; YetiYell stops a run when the tab is hidden.
